# どうぶつ保護データプロジェクト — SaaS 要件定義書

**バージョン**: 1.0 / **作成日**: 2026年6月9日 / **主催**: Japan Animal Shelter Alliance（JASA）
**対象システム**: どうぶつ保護データ管理SaaS（仮称：JASA Data Hub）

> このファイルは発注元の要件定義書（v1.0）を保持したもの。プロジェクトの一次情報源。
> 「どう作るか」の実装判断は本リポジトリの [CLAUDE.md](../CLAUDE.md) と各マイグレーション/コードに反映する。

## 1. プロジェクト背景

### 1.1 解決したい課題
日本では行政施設の収容数（2024年度の引取り数 39,409頭など）は環境省が公表するが、
**民間の動物保護団体・個人活動者が保護・管理している動物のデータは統一形式で継続集計されていない**。
そのため、全国でどれだけの動物が保護を必要としているか／行政から民間へどれだけ引き継がれているか／
団体間連携や不適切飼養環境（多頭飼育崩壊・ネグレクト）対応がどの程度行われているかを全国レベルで把握できていない。

### 1.2 狙い
民間団体の **新規収容・転帰・管理頭数・TNR件数** を統一フォーマットで毎月記録する基盤づくり。
1. 各団体が自団体の活動を振り返り・説明・意思決定に使える
2. 都道府県・全国レベルで保護活動の実態を可視化できる
米国・カナダの Shelter Animals Count（SAC）の Intake & Outcome Database を参考に、日本の現場に即して項目設計。

### 1.3 位置づけ
現状はExcelの「犬用・猫用 月次報告書」を各団体が記入・提出する想定。
本SaaSはこの月次報告書の**データ収集・集計・可視化・データ還元のプロセスをシステム化**する。
実施期間は 2026年4月〜2027年3月（パイロット年度）。

---

## 2. システムの目的（ゴール）

| # | 目的 | 達成されると何が変わるか |
|---|------|------------------------|
| G1 | 月次データを統一フォーマットで蓄積 | 比較・集計可能な構造化データにする |
| G2 | JASA事務局の代行入力を効率化 | 紙・Excel転記を減らし入力ミスと工数を削減 |
| G3 | 収支の整合性を担保 | 「月初＋収容＝転帰＋月末」の論理破綻を入力時に検知 |
| G4 | 都道府県・全国の集計を自動化 | 手集計をなくし最新の全国統計を出せる |
| G5 | 団体へデータを還元 | 年次報告・支援者向け資料に使えるグラフ・帳票を提供 |

### 2.1 KPI 案
- パイロット年度内に **30団体以上** の月次データ登録
- 月次データの**収支整合エラー率 5%未満**（入力時バリデーションで担保）
- 事務局1件あたり入力時間を Excel比 **50%削減**
- 四半期ごとのデータ還元レポートを全参加団体に自動生成

## 3. スコープ

### 3.1 In Scope（パイロット年度）
- 犬・猫の月次データ（新規収容・転帰・管理頭数・TNR）の記録・編集
- 団体マスタ・施設/活動者の管理
- 都道府県・全国の集計と可視化（ダッシュボード）
- 団体向けデータ還元（年次・四半期レポート出力）
- 収支整合バリデーション
- CSV / Excel インポート・エクスポート（既存Excel報告書からの移行用）
- ユーザー権限管理（JASA事務局 / 団体ユーザー / 閲覧者）

### 3.2 Out of Scope（将来検討）
- 個体単位の詳細管理（健康記録・写真・里親マッチング）※ShelterMate側の領域
- 寄付・会費決済機能
- 一般公開ポータル（匿名集計の外部公開）※将来フェーズ
- 多言語対応（当面は日本語のみ）
- モバイルネイティブアプリ（当面はレスポンシブWeb）

### 3.3 段階的リリース方針
| フェーズ | 内容 | 入力者 |
|---------|------|--------|
| Phase 1（MVP） | 事務局による**手入力（代行入力）** + 集計ダッシュボード | JASA事務局のみ |
| Phase 2 | 団体ユーザーによる自己入力、データ還元レポート自動生成 | 事務局 + 団体 |
| Phase 3 | 匿名化した全国統計の公開ポータル | 一般閲覧 |

> 本パイロットは「JASA事務局が代行入力する」運用が前提のため、Phase 1 を最優先。

## 4. 利用者と役割

| ロール | 想定人物 | 主な操作 |
|--------|---------|---------|
| **事務局管理者（Admin）** | JASA事務局スタッフ | 全団体のデータ代行入力・編集、団体マスタ管理、ユーザー管理、全国集計閲覧、レポート出力 |
| **団体ユーザー（Org User）** | 参加団体の担当者 | 自団体のデータ入力・閲覧、自団体レポート出力（Phase 2〜） |
| **閲覧者（Viewer）** | 理事・分析担当 | 集計ダッシュボードの閲覧のみ（編集不可） |

団体ユーザーは**自団体のデータのみ**アクセス可能。事務局は全団体にアクセス可能。
匿名性保持のため団体ユーザーは他団体の個別データを閲覧できない（全国集計の匿名値のみ）。

## 5. 記録するデータ（業務モデル）

記録は **団体 × 種別（犬/猫）× 報告対象期間** を1単位とする。提出様式の項目に完全準拠。

### 5.0 年齢区分（収容・転帰の共通列）
すべての収容・転帰は次の3区分ごとに頭数を記録（「合計」列は自動計算）。

| 区分コード | 表示 |
|-----------|------|
| 〜5ヶ月齢 | 〜5ヶ月齢 |
| 5ヶ月〜10歳 | 5ヶ月〜10歳 |
| 10歳〜 | 10歳〜 |

### 5.1 新規収容（Intake）
各カテゴリーを年齢区分3列で記録。地域区分を持つカテゴリーは地域×年齢のマトリクス。

| 収容カテゴリー | 地域区分 | 種別 | 定義 |
|---------------|---------|------|------|
| 所有者不明 | あり | 共通 | 飼い主のいない/屋外を放浪する動物が市民から持ち込まれた、または捕獲依頼があった場合 |
| 飼い主からの引き取り | あり | 共通 | 所有者により収容依頼があった動物（過去に団体から譲渡した動物の返却を含む） |
| 行政施設からの引き取り | あり | 共通 | 行政施設から引き出した動物 |
| 他の民間団体からの移動 | あり | 共通 | 他団体から移動してきた動物（キャパシティ超過への協力、譲渡促進のための移動 等） |
| 不適切飼養環境からの収容 | あり | 共通 | ネグレクト・動物虐待・多頭飼育崩壊など健康/ウェルフェアが損なわれた状態からの収容 |
| TNR経由からの収容 | なし | **猫のみ** | TNR活動の中で捕獲後、保護が必要と判断され収容された動物 |
| その他 | なし | 共通 | 上記いずれにも該当しない収容理由（例：シェルター出生、体調悪化した地域猫 等） |
| **合計** | — | — | 新規収容の総数（自動計算） |

> 地域区分「あり」のカテゴリーは 県内 / 県外：隣接 / 県外：遠隔 の3行を持つ。

### 5.2 転帰（Outcome）
**非生存転帰**

| カテゴリー | 地域区分 | 種別 | 定義 |
|-----------|---------|------|------|
| 死亡 | なし | 共通 | 収容中に死亡した動物 |
| 行方不明・失踪 | なし | 共通 | 所在が不明となった動物 |
| 安楽死 | なし | 共通 | 獣医師の判断により安楽死が実施された動物 |
| **合計** | — | — | 非生存転帰の総数（自動計算） |

**生存転帰**

| カテゴリー | 地域区分 | 種別 | 定義 |
|-----------|---------|------|------|
| 一般譲渡 | あり | 共通 | 正式な譲渡手続きを経て一般家庭への譲渡が成立した動物 |
| 飼い主への返還 | なし | 共通 | 元の飼い主に返還された動物 |
| 他の民間団体への引渡し | あり | 共通 | 他団体へ移動させた動物 |
| 屋外へのリリース | なし | **猫のみ** | 不妊手術後にリリースした動物 |
| その他 | なし | 共通 | 上記いずれにも該当しない生存転帰 |
| **合計** | — | — | 生存転帰の総数（自動計算） |

### 5.3 現在の管理頭数（Population Count）
- 記録開始時（期間の開始日）と記録終了時（終了日）の管理下動物の合計頭数
- それぞれ「そのうち一時預かりボランティア先で管理中」の頭数（内数）も記録
- 対象は施設内・施設外、スタッフ自宅、一時預かり先、終生飼養中などすべて（個人のペットは含めない）

### 5.4 TNR頭数（猫のみ・実施団体のみ）
TNR活動の頭数を実施形態別に記録（独自の対象期間を持つ）。

| 項目 | 内容 |
|------|------|
| 団体が単独で実施 | 団体単独でのTNR頭数（匹） |
| 他団体と協力して実施 | 他団体と協力したTNR頭数（匹） |

> 「TNR経由からの収容」（§5.1）とは別物。TNR頭数は活動量、TNR経由収容はそのうち保護に至った頭数。

### 5.5 収支の整合式（重要なビジネスルール）
```
記録終了時の管理頭数 = 記録開始時の管理頭数 ＋ 新規収容合計 − 転帰合計（生存＋非生存）
```
入力時に差分を計算し、不一致なら**警告**を表示（強制エラーにするかは運用判断 → 設定化）。
一時預かり内数（§5.3）は合計の一部であり本式には含めない（参考値）。

## 6. 機能要件

| ID | 機能 | 概要 | 優先度 |
|----|------|------|--------|
| F-01 | 認証・ログイン | メールログイン、ロール別権限 | 必須 |
| F-02 | 団体マスタ管理 | 団体の登録・編集・所在都道府県・活動形態 | 必須 |
| F-03 | 月次レポート入力 | 団体×種別×月の収容・転帰・管理頭数・TNRの入力フォーム | 必須 |
| F-04 | 収支整合バリデーション | 月初＋収容＝転帰＋月末の検算と警告 | 必須 |
| F-05 | レポート一覧・編集 | 入力済みレポートの検索・絞り込み・修正 | 必須 |
| F-06 | 提出ステータス管理 | 下書き / 提出済み / 確定 の遷移 | 必須 |
| F-07 | 集計ダッシュボード | 全国・都道府県・期間別の収容/転帰の集計と可視化 | 必須 |
| F-08 | CSV/Excel インポート | 既存Excel報告書の一括取込（主運用は手入力。将来の補助） | 中 |
| F-09 | CSV/Excel エクスポート | 集計データ・生データの書き出し | 高 |
| F-10 | 団体向けデータ還元レポート | 団体別の年次/四半期サマリー（グラフ付き） | 中（Phase 2） |
| F-11 | ユーザー・権限管理 | ユーザー招待、ロール付与 | 必須 |
| F-12 | 監査ログ | 誰がいつ何を変更したか | 中 |
| F-13 | マスタ管理 | 収容/転帰カテゴリー・年齢区分・都道府県等の編集 | 高 |

### 6.2 主要ユースケース
- **UC-1**: 事務局が団体の月次データを代行入力（団体・種別・対象月を選択 → 入力 → 収支チェック → 提出済み保存）
- **UC-2**: 全国の収容実態を確認（ダッシュボードを期間・都道府県・種別でフィルタ → グラフ確認 → CSVエクスポート）
- **UC-3**: 団体へ四半期データを還元（団体・四半期指定 → サマリーレポート生成 → PDF/Excel出力）

## 7. 非機能要件

| 区分 | 要件 |
|------|------|
| 規模 | 団体数 〜100、月次レポート 〜2,400件/年。小〜中規模。 |
| 同時利用 | 事務局中心、〜10人程度。高負荷設計は不要。 |
| 可用性 | 平日日中中心、99%程度（厳格SLA不要）。 |
| セキュリティ | ログイン必須、ロール分離、HTTPS、パスワードハッシュ化。 |
| プライバシー | 公開時は必ず匿名化集計。団体名特定の外部公開・第三者提供は行わない。 |
| データ保全 | 日次バックアップ、論理削除（物理削除しない）。 |
| 監査性 | 主要データの変更履歴を記録。 |
| 保守性 | 一般的でモダンな構成。 |
| 国際化 | 当面は日本語のみ。将来の英語対応に備え文言を分離可能に。 |
| アクセシビリティ | レスポンシブWeb。PC主・タブレット対応。 |

## 8. 前提・制約・リスク

### 8.1 前提
- 開発はClaude Codeを用いる。ドキュメント豊富なモダン構成を採用。
- パイロット年度はJASA事務局による代行入力を主運用とする。
- 記録項目は提出様式に準拠。年齢区分は「〜5ヶ月齢／5ヶ月〜10歳／10歳〜」で確定。
- 将来の様式改訂に備え、収容/転帰カテゴリー・年齢区分はマスタとして編集可能に。

### 8.2 制約
- 比較・評価を目的としない（団体間の優劣を示すシステムではない）。比較ランキング的表現を避ける。
- 個体単位の管理はスコープ外（ShelterMateとの役割分担）。

### 8.3 主なリスクと対応
| リスク | 影響 | 対応 |
|--------|------|------|
| 項目定義が現場で揺れる | データ不整合 | カテゴリー・年齢区分をマスタ化し後調整可能に |
| Excel移行が煩雑 | 導入障壁 | インポート機能とテンプレート提供（F-08） |
| 匿名性への不安 | 参加離脱 | 権限分離・匿名集計を仕様で明確に担保 |
| 入力負荷が高い | 未提出増加 | 代行入力UI最適化・前月値コピー等の補助 |
